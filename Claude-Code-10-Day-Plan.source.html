Part I — Must-know concepts

Ten ideas, each in a few lines. Everything in the ten days is an application of one of these.

1. The context window is the whole game

Every turn Claude sees one prompt assembled from: system prompt → built-in tool definitions (~17K tokens) → MCP tool definitions → your CLAUDE.md layers and rules → auto-memory → skill descriptions → the conversation. Quality falls and cost rises as this grows; the model remembers the start and the end of a prompt best (primacy / recency), so guardrails belong at the top of CLAUDE.md. /context shows the exact breakdown; you have never run it.

2. Instruction layers and load order

Loaded at launch and concatenated (not overridden), in this order: managed/enterprise → ~/.claude/CLAUDE.md (you, all projects) → every CLAUDE.md from the filesystem root down to the working directory → CLAUDE.local.md after its sibling. Files in subdirectories (your client-app/CLAUDE.md) load on demand when Claude reads a file there. .claude/rules/*.md splits a long file into topics; a rule with a paths: glob loads only when matching files are touched. @path imports pull other files in at launch.

3. CLAUDE.md versus auto-memory — and why neither is enforcement

CLAUDE.md is what you write to steer Claude. Auto-memory (~/.claude/projects/<project>/memory/, indexed by MEMORY.md) is what Claude writes for itself: user, feedback, project and reference notes. Both are read as context and can be forgotten under pressure. Anything that must never happen — dotnet ef database update, dotnet build — needs a PreToolUse hook, which is code, not persuasion (Day 6).

4. The extension mechanisms and what each costs

MechanismUse it whenContext cost

The course's most practical rule: prove a workflow with an MCP in five minutes, then convert it into a skill that calls the API or a script directly.

5. Permission modes, and the one you are in

Modes cycle with Shift+Tab: default (ask before edits) → accept-edits → plan (read-only exploration) → bypass. Your user settings set defaultMode: auto, where the harness allows/denies calls automatically and asks only for risky ones; /permissions shows the allow/ask/deny rules. Your project settings.local.json has grown to ~15 KB of one-off allow rules — Day 1 cleans it.

6. Plan → build → verify, with checkpoints

Plan mode researches and writes a spec before touching files; "a minute of planning saves ten of building" and cuts tokens because Claude stops exploring alternatives mid-build. Every file edit is checkpointed: Esc Esc or /rewind restores code and/or conversation. The verify step is what most people skip — tests, a browser screenshot, a rendered PDF, a diff review — and it is where Claude's speed pays off: 80% → 95% → 99% in minutes.

7. Compaction and session lifecycle

Auto-compact fires near the limit; /compact <what to keep> lets you steer the summary. /clear for unrelated work (you do this 139 times — good). /resume and /rename for named threads (122 resumes — good). New for you: /branch (fork the conversation in place), /fork (copy to a background session), /btw (side question that does not enter history), /export.

8. Models, effort, thinking

/model switches model; /effort sets reasoning depth. Extended thinking is billed but not kept in the conversation, so "reason as much as you like, answer tersely" is cheap. Sonnet for high-volume, low-judgement work (log reading, data pulls); Opus for design and synthesis. Fast mode (/fast) trades price for latency.

9. The parallelism ladder

Single session → subagents (own context, summary back to parent) → agent teams (full independent instances that message each other; roughly 7× tokens) → git worktrees (separate folders, no file collisions, merge at the end). Probabilities multiply: ten subagents at 95% each succeed together only 59% of the time — keep task definitions tiny and return summaries, not raw data. Your CLAUDE.md forbids unrequested subagents; the ladder is something you climb deliberately (Day 8).

10. Security realities

Secrets do not belong in committed instruction files (your dev login is in CLAUDE.md; a GitHub token sits in important-commands.txt — Appendix B). Bypass mode plus rm -rf is a real failure mode; a deny rule or hook removes it. Anything vibe-coded that handles credentials or money needs a human review before it is exposed.

B. Long sessions: what you get, what it costs, and the practice that replaces it

What your belief gets right

The conversation is the only place the last three hours of reasoning live. Nothing else knows that the void-payment path was rewritten twice or why you rejected the first Telerik approach. Continuity is real.

What it gets wrong — from the docs and from your history

  1. Every turn re-sends everything. A one-line question in a session that has been open all day carries the whole conversation, and each tool batch inside a turn is another request carrying it again. Cached tokens are cheaper, not free, and they still take time to read.
  2. The continuity is already lossy. When the window fills, auto-compaction replaces the history with a summary. After the first compaction you no longer have "the context" — you have Claude's précis of it, chosen without your priorities. And compacting a large session is itself a large request.
  3. Quality degrades before cost does. Rules from CLAUDE.md sit at the far end of a 300K prompt; three abandoned approaches remain in view and pull later answers toward them; a fix from hour one is re-broken in hour four because the instruction that motivated it is buried. This is what the course calls context rot, and the docs' advice is blunt: "unexpectedly high spend usually traces back to long sessions that were never cleared."
  4. Breaks punish long sessions most. The cache expires after an hour (five minutes on usage credits). Coming back to a huge session after lunch means re-processing all of it at full price and full latency. Pro/Max users are offered resume from a summary for exactly this reason.
  5. The durable context survives /clear. CLAUDE.md, rules, auto-memory, plan files, the git diff and a handoff note are all still there. A fresh session that reads a 15-line handoff plus git diff usually outperforms the 300K-token session it replaces — and answers faster (section A, lever 1).

The practice: one session = one task with a definition of done

The handoff, so clearing costs nothing

Before /clear:  "Write a handoff for a fresh session: goal · what is done · what is next · open errors (verbatim) ·
                decisions and why · files touched. Save anything non-obvious and durable to memory."
Then:           /rename <task-name>   →   /clear
Fresh session:  "Read the handoff in memory for <task-name>, run git diff --stat, then continue with step N."

Add a # Compact instructions section to CLAUDE.md ("preserve exact error text, file list, and decisions; drop tool output") so even automatic compaction keeps what you care about.

Applied to your recent work. The KendoReact v16 migration (152 files) and the project-report rebuild each lived in long threads. The cheaper shape: one session per batch of files or per plan step, a MIGRATION-STATUS.md or plan file as the shared state, a handoff at each batch boundary. Same continuity, a fraction of the tokens, and each session starts at the fast end of the latency curve.
Rule of thumb. If you would need more than two sentences to tell a colleague what this session is about, it is two sessions. If a fresh session with the handoff could not continue the work, the handoff — not the session — is what needs fixing.

6Hooks as hard guardrails~40 min

Goal

A chime when Claude stops or needs you; a PreToolUse guard that makes your build and migration rules impossible to break; a log of what got blocked.

Why it matters for you

Today "NEVER run dotnet build" is a sentence in a markdown file. It has held, but it is context, not policy, and it competes with everything else in the window after a compaction. A hook is a shell script that runs before every Bash call and exits 2 to block — no model judgement involved. The chime is the course presenter's single most-used trick for running several sessions without idling any of them.

Try today

  1. Create .claude/hooks/guard-bash.sh (no jq on this Mac, so Python parses stdin): 
    #!/bin/bash
cmd=$(python3 -c 'import sys,json; print(json.load(sys.stdin).get("tool_input",{}).get("command",""))')
if echo "$cmd" | grep -Eq 'dotnet +(build|run|watch)|dotnet ef database update|dotnet ef migrations remove|npm run (build|start)|yarn (build|start)|rm -rf'; then
  echo "BLOCKED by .claude/hooks/guard-bash.sh: '$cmd' — CLAUDE.md hard rule (builds/migrations are manual)." >&2
  echo "$(date '+%F %T') $cmd" >> "$CLAUDE_PROJECT_DIR/.claude/hooks/blocked.log"
  exit 2
fi
exit 0
    chmod +x .claude/hooks/guard-bash.sh and add .claude/hooks/blocked.log to .gitignore.
  2. Create .claude/settings.json (shared, committed) with the guard, and put the sounds in your user settings so they follow you to every project: 
    // .claude/settings.json
{ "hooks": { "PreToolUse": [ { "matcher": "Bash",
    "hooks": [ { "type": "command", "command": "\"$CLAUDE_PROJECT_DIR\"/.claude/hooks/guard-bash.sh" } ] } ] } }

// ~/.claude/settings.json  (merge into the existing object)
{ "hooks": {
    "Stop":         [ { "hooks": [ { "type": "command", "command": "afplay /System/Library/Sounds/Glass.aiff" } ] } ],
    "Notification": [ { "hooks": [ { "type": "command",
        "command": "osascript -e 'display notification \"Claude needs input\" with title \"Claude Code\"'" } ] } ]
} }
  3. Restart the session, type /hooks and confirm all three appear with their source file.
  4. Test the guard on purpose: "run dotnet build to check". Expect the block message in the conversation and a line in blocked.log. Test the chime by asking any question.
  5. Optional: a PreCompact hook that appends git status --short to a scratch file, so a post-compaction session can recover which files were in flight.

Done when

A build attempt is blocked mechanically, the chime plays on Stop, and .claude/settings.json is committed so every clone of the repo gets the guard.

Keep or drop

Keep both. If the chime annoys you in single-session work, keep Notification and drop Stop.
